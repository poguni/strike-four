# 숫자야구 게임(Strike Four) 앱 — 단계별(Phase) 구현 프롬프트

Claude Code에 그대로 붙여넣어 사용하는 단계별 프롬프트입니다. 각 Phase는 이전 Phase가 완료된 뒤 순서대로 진행하세요.

**시작 전 준비물**
1. 레포 루트에 `PRD.md` 파일 저장 (PRD 문서 내용을 복사해서 저장: https://claude.ai/code/artifact/da3e7862-10d5-4eb3-9a87-c6be775decbc )
2. 레포 루트에 `DESIGN.md` 저장 (이미 전달받은 파일)
3. Supabase 프로젝트 생성 후 Project URL / anon key 확보 (Phase 4에서 사용). Free Tier는 계정당 활성 프로젝트 2개 제한이 있으니, 기존에 활성화된 다른 프로젝트가 있다면 이 앱 사용 시간 동안 일시정지할지 미리 확인

**목표**: 레포 구조를 잡고 문서를 배치한다. 아직 화면은 만들지 않는다.

```
프롬프트:
이 레포는 "숫자야구 게임 앱"을 만드는 프로젝트야. 같은 폴더에 PRD.md와 DESIGN.md가 있으니 먼저 두 파일을 읽고 프로젝트 전체 구조를 파악해줘.

작업:
1. index.html 하나로 시작하는 바닐라 JS 프로젝트 구조를 만들어줘 (styles.css, app.js로 분리해도 되고, 단일 HTML 파일로 시작해도 좋아 - 네가 보기에 더 관리하기 쉬운 쪽으로 제안해줘)
2. GitHub Pages 배포를 전제로 한 기본 골격(README.md에 실행/배포 방법 간단히 기록)

4. PRD.md와 DESIGN.md 내용을 참고해서 앞으로 어떤 순서로 구현할지 너의 이해를 3~4줄로 요약해서 알려줘 (아직 코드는 최소한만)
```

**완료 기준**
- [ ] `index.html`이 브라우저에서 빈 페이지라도 정상 로드됨
- [ ] `README.md`에 실행 방법이 적혀 있음
- [ ] Claude Code가 PRD.md, DESIGN.md 내용을 정확히 요약해서 보여줌 (엉뚱하게 이해하고 있지 않은지 확인)

## Phase 1. 테마 시스템 & 메인 화면 정적 레이아웃

**목표**: DESIGN.md의 CSS 변수 체계로 파스텔톤/모던 클린 테마를 구현하고, 메인 화면(정적 UI)을 완성한다.

```
프롬프트:
DESIGN.md를 참고해서 테마 시스템을 구현해줘.

작업:
1. DESIGN.md의 "3. 디자인 토큰(CSS 변수)" 섹션 값을 그대로 사용해서 [data-theme="pastel"], [data-theme="modern"] 스타일을 구현
2. DESIGN.md "1. 테마 전환 방식"의 JS 로직대로 localStorage 기반 테마 저장/복원 구현
3. DESIGN.md "2. 드롭다운 UI 스펙"대로 메인 화면 우측 상단에 테마 선택 드롭다운 추가
4. PRD.md "화면 구성(IA)"의 메인 화면 요소를 모두 정적으로 배치: 로고/타이틀, 프로필 카드(이름/닉네임+전적), 혼자 연습하기/학급 세션 만들기(교사용)/세션 참가하기/실시간 랭킹 버튼
5. 버튼 클릭은 아직 동작 안 해도 됨 (다음 Phase에서 연결)
6. 360px(모바일)부터 1920px(PC)까지 레이아웃이 깨지지 않는지 직접 확인해줘
```

**완료 기준**
- [ ] 드롭다운에서 테마를 바꾸면 새로고침 없이 전체 화면 색상/폰트/모양이 즉시 바뀜
- [ ] 새로고침해도 마지막으로 선택한 테마가 유지됨
- [ ] 최초 방문(로컬스토리지 비어있음) 시 파스텔톤이 기본으로 보임
- [ ] 두 테마 모두 DESIGN.md 시안과 비교했을 때 톤·레이아웃이 크게 다르지 않음
- [ ] 모바일 폭(360px)과 데스크톱 폭(1920px)에서 각각 스크린샷을 찍어 깨짐이 없는지 확인함

## Phase 2. 닉네임 & 로컬 사용자 식별

**목표**: 로그인 없이 닉네임 기반으로 "나"를 식별하는 기반을 만든다. (혼자 연습하기, 랭킹 모두 이 위에서 동작)

```
프롬프트:
PRD.md의 "대상 사용자 및 사용 환경 - 이용 방식"과 "기능 3. 리더보드/랭킹 - 식별 방식"을 참고해서 로컬 사용자 식별 기능을 구현해줘.

작업:
1. 최초 방문 시 닉네임 입력 UI (모달 또는 인라인)
2. 닉네임 + 서버 발급 익명 ID(uuid)를 localStorage에 저장
3. 프로필 카드(Phase 1에서 만든 부분)에 실제 닉네임을 표시하고, 연필 아이콘으로 닉네임 수정 가능하게
4. 재방문 시 저장된 닉네임을 자동으로 불러와서 입력 화면을 건너뜀
```

**완료 기준**
- [ ] 최초 방문 시 닉네임을 입력하지 않으면 다음 단계로 진행할 수 없음
- [ ] 닉네임 입력 후 새로고침해도 다시 묻지 않음
- [ ] 프로필 카드의 이름과 연필 아이콘 수정이 정상 동작
- [ ] 시크릿 모드/다른 브라우저에서 접속 시 새 사용자로 취급됨 (PRD의 알려진 한계와 일치)

## Phase 3. 혼자 연습하기 (vs AI)

**목표**: 숫자야구 핵심 로직과 AI 상대를 구현한다. 이 Phase는 서버(Supabase) 없이 완전히 프론트엔드에서 동작해야 한다.

```
프롬프트:
PRD.md의 "게임 규칙"과 "기능 1. 혼자 연습하기(vs AI)"를 참고해서 연습 모드를 구현해줘.

작업:
1. 숫자야구 판정 로직 함수 작성: 4자리 중복 없는 정답 생성, 입력값과 비교해 스트라이크(S)/볼(B)/아웃(O) 계산
2. 난이도 3단계(쉬움/보통/어려움) AI 추론 로직: PRD 표에 설명된 방식대로 구현 (쉬움=순수 랜덤, 보통=힌트 일부 반영, 어려움=제약 전파 기반 최적 추론)
3. 연습 경기 화면: 숫자 키패드 입력, 공격 기록판(시도 번호/입력값/S B 결과 누적 표시), 남은 시도 횟수 표시
4. 게임 종료 처리: 4스트라이크 시 홈런(승리) 화면, 소진 시 실패 화면
5. 이 결과는 리더보드에 반영하지 않음 (PRD 명시사항)
```

**완료 기준**
- [ ] 판정 로직에 대해 알려진 정답(예: 1234)과 여러 입력값 조합으로 S/B/O가 정확히 계산되는지 직접 검증함 (최소 5개 케이스)
- [ ] 난이도별로 AI의 추론 속도/정확도 체감 차이가 있음 (어려움이 쉬움보다 평균적으로 더 적은 시도로 정답을 맞춤)
- [ ] 시도 횟수(기본 10회) 소진 시 실패 화면이 뜨고 더 이상 입력이 안 됨
- [ ] 4스트라이크 즉시 게임이 종료되고 홈런 화면이 뜸
- [ ] 연습 결과가 리더보드/전적에 반영되지 않음을 확인

## Phase 4. Supabase 연동 — 학급 세션 생성 & 랜덤 매칭

**목표**: 실시간 서버 연동의 첫 단계로, 세션 생성/참가와 대기열 기반 자동 매칭까지 구현한다. 실제 게임 플레이(턴 진행, 판정)는 다음 Phase에서 다룬다. 이 부분이 이번 프로젝트에서 가장 새롭고 까다로운 영역이라 별도 Phase로 분리했다.

```
프롬프트:
PRD.md의 "기능 2. QR 대전(학급 세션 랜덤 매칭 / 친구 초대)"과 "기술 스택 및 아키텍처 제안"을 참고해서 Supabase 기반 세션·매칭 엔진을 구현해줘.
Supabase 프로젝트 URL과 anon key는 .env(또는 config.js, .gitignore 처리)로 관리해줘.

작업:
1. PRD의 "간이 ERD"를 참고해서 Supabase에 테이블 생성: sessions(id, teacher_id, capacity, status, created_at), session_players(session_id, player_id, nickname, state), rooms(id, session_id, player_a, player_b, status)
2. 교사용 "학급 세션 만들기": 정원 제한 없는 세션 생성 → 세션 코드(6자리)와 QR 이미지 생성(qrcode.js 등 CDN 라이브러리 활용). 교사도 학생과 동일한 패턴으로 최초 세션 생성 시 익명 teacher_id(uuid)를 발급해 localStorage에 저장
3. 학생용 세션 참가: QR 스캔 시 자동 접속 URL 이동 / 6자리 세션 코드 직접 입력 옵션 모두 지원 → 이름/닉네임 입력 후 대기열(로비) 화면 진입
4. 학생용 "친구 초대": 대기열 화면에서 정원 2명짜리 세션을 새로 생성해 QR/코드를 특정 친구에게만 공유
5. Supabase Realtime Presence로 세션별 대기 인원을 추적하고, 대기열에 2명 이상 모이면 2명씩 랜덤으로 짝지어 rooms 레코드를 생성
6. 같은 teacher_id로 생성된 세션끼리만 매칭이 일어나는지, 다른 세션의 학생과는 섞이지 않는지 반드시 확인
7. 매칭이 성사되면 두 플레이어를 해당 room으로 자동 이동(별도 "준비 완료" 버튼 없이)
```

**완료 기준**
- [ ] 교사 세션 생성과 학생 참가 화면에서 서로 다른 두 기기(또는 브라우저 탭)로 QR/코드 입장이 실제로 됨
- [ ] 같은 세션에 3명 이상이 대기 중일 때, 2명씩 자동으로 짝지어지고 나머지는 계속 대기함
- [ ] 서로 다른 교사가 각자 세션을 열었을 때, 두 세션의 학생이 절대 서로 매칭되지 않음
- [ ] 친구 초대(정원 2) 세션은 두 번째 사람이 들어오는 즉시 매칭됨
- [ ] 매칭이 성사되면 두 플레이어 화면이 자동으로 게임 화면으로 전환됨

## Phase 5. 실시간 게임 진행 (턴 동기화 & 판정)

**목표**: Phase 4에서 매칭되어 생성된 room 위에서 실제 숫자야구 대결을 실시간으로 진행한다.

```
프롬프트:
PRD.md의 "게임 규칙"과 "기능 2. QR 대전" 중 "실시간 동기화"/"게임 종료" 부분을 참고해서 실시간 대전 로직을 구현해줘.

작업:
1. Supabase Realtime Broadcast로 양쪽의 공격 입력과 판정 결과를 즉시 동기화 (1초 이내 반영 목표)
2. 턴 표시(내 차례/상대 차례)와 턴당 30초 제한 타이머 구현, 시간 초과 시 턴 자동 스킵
3. 승패 판정: 먼저 4스트라이크 맞춘 쪽 승리, 둘 다 10회 내 실패 시 무승부
4. 상대방 이탈/재접속 시 처리: 20~30초 대기 후 부전승 판정
5. 게임 종료 후: 학급 세션이면 두 플레이어를 다시 대기열(로비)로 복귀시켜 재매칭 가능하게 하고, 친구 초대 세션이면 재시작 여부를 선택하게 함
6. 게임 결과를 leaderboard 집계용 테이블에 teacher_id와 함께 기록 (Phase 6에서 사용)
```

**완료 기준**
- [ ] 한쪽에서 숫자를 입력하면 반대쪽 화면에 1초 안팎으로 결과가 반영됨
- [ ] 턴이 서로 꼬이지 않고(동시 입력 방지) 순서대로 진행됨
- [ ] 30초 턴오버가 실제로 동작하고, 시간 초과 시 상대 턴으로 자동 전환됨
- [ ] 먼저 4스트라이크를 맞춘 쪽에 승리 화면이, 상대에게 패배 화면이 뜸
- [ ] 한쪽이 새로고침(재접속)해도 게임 상태가 유지됨
- [ ] 한쪽이 완전히 이탈하면 대기 후 남은 플레이어에게 부전승 처리됨
- [ ] 학급 세션은 게임 종료 후 두 플레이어가 대기열로 돌아가 다른 상대와 재매칭됨

## Phase 6. 리더보드 / 랭킹

**목표**: QR 세션 대전 결과를 학급(교사) 단위 랭킹으로 보여준다.

```
프롬프트:
PRD.md의 "기능 3. 리더보드/랭킹(학급 단위)"을 참고해서 학급별 실시간 랭킹 화면을 구현해줘.

작업:
1. Phase 5에서 쌓인 대전 결과를 teacher_id + player_id 기준으로 집계하는 leaderboard 뷰 또는 쿼리 작성(같은 교사 세션에 참여한 학생들끼리만 집계)
2. PRD 표의 지표를 모두 표시: 순위, 승-패, 승률, 최소 시도 횟수 홈런(보너스 지표)
3. 최소 대전 수(예: 3전 이상) 미만인 사용자는 랭킹에서 제외
4. 메인 화면의 "실시간 랭킹" 버튼으로 진입하는 랭킹 화면 UI 구현 — 내가 마지막으로 참여한 교사(학급)의 랭킹을 기본 표시, 상위 N명 리스트 + 내 순위 강조 표시
```

**완료 기준**
- [x] Phase 5에서 대전을 마치면 잠시 후 해당 학급 랭킹에 결과가 반영됨 (`finish_room()`이 대전 종료 즉시 `match_results`에 기록, 랭킹 화면 진입 시마다 재조회)
- [x] 승률 계산이 (승 수 / 총 대전 수) 기준으로 정확함 (테스트 데이터로 2승1패→67%, 1승2패→33% 검증 완료)
- [x] 최소 대전 수 조건 미만 사용자가 랭킹에 노출되지 않음 (기본 3전, `leaderboard.js`의 `RANKING_MIN_GAMES`)
- [x] 다른 교사(학급) 세션 결과가 내 학급 랭킹에 섞이지 않음 (`teacher_id`로 필터링해 조회)
- [x] 내 순위가 리스트 안에서 시각적으로 구분되어 보임 (`.ranking-row.is-me` 강조 테두리)

## Phase 7. QA & 배포

**목표**: 비기능 요구사항을 점검하고 GitHub Pages로 실제 배포한다.

```
프롬프트:
```
